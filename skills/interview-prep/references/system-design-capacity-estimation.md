# 系统设计 — 容量估算入门框架

当用户第一次做系统设计题、不知道如何估算时，先教框架再推进。

## 三步法

### 第一步：拆指标

| 指标 | 公式 |
|------|------|
| 写入 QPS | 日均写入量 ÷ 86400 |
| 读取 QPS | 写入 QPS × 读写比 |
| 峰值 QPS | 平均 QPS × 2~3（经验系数） |

### 第二步：算存储

逐字段估算每条数据大小：

| 字段类型 | 常见估算 | 说明 |
|---------|---------|------|
| 短 ID / 短码 | 6-8B | base62 编码 7 位 ≈ 7B，VARCHAR 余量 ≈ 8B |
| URL | 200B | 普通 URL 50-80B，含 query/UTM 可 1KB+，取 200B 均值 |
| 时间戳 | 4-8B | DATETIME 占 5B，BIGINT 占 8B，估算时一致即可 |
| 状态/类型 | 1-4B | TINYINT 1B，INT 4B |

总存储 = 日均条数 × 保留天数 × 单条大小

### 第三步：加缓存和带宽

- 缓存：热点数据按 20% × 总存储 估算，实际按 key+value 双算
- 带宽：读取 QPS × 平均响应大小

## 面试时说

> "日均 X 条写入，按 86400 秒算大约 Y/s，读写比 Z:1 的话读大约 W/s。存储按每条 KB、保留 D 天约 TB。读压力大的话热点放 Redis。"

**关键原则：精确数字不重要，计算方法 + 量级感才重要。**

## 常见估算参考值

| 项目 | 值 | 来源 |
|------|-----|------|
| 普通 URL 平均长度 | 200B | Google 短链接论文经验值 |
| 短码长度 | 7-8B | base62 编码 7 位 |
| DATETIME 存储 | 5B | MySQL 内部实现 |
| Unix 时间戳 | 8B | BIGINT |
| 80/20 缓存比例 | 20% 热数据 | Pareto 原则 |
| 峰值系数 | 2-3× 平均 | 工程经验 |
